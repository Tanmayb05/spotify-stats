**Date:** 2026-09-01 10:30:36
**Status:** Completed

## Overview

`docker compose up` now brings up Postgres + API + web with **no Supabase account
and no credentials of any kind**, while `DB_BACKEND=supabase` (still the default)
leaves the deployed demo byte-identical.

Before this phase the API could not start without Supabase credentials at all:
`supabase_data_loader.py` built a `SupabaseDataLoader()` at import time and every
route module imported it at module scope, so `import app.main` raised
`ValueError` on a fresh clone. That was Phase 9's one open follow-up and the
blocker for Phases 11–12, which need a local Postgres to build the star schema
and run Dagster against.

## What Was Implemented

### Purpose

Make the project runnable and reviewable without accounts, and give Phases 11–16
a local Postgres to build on — without forking the data-access layer into two
divergent code paths.

### Features

**1. Backend adapter (`app/db/backends.py`).** `SupabaseDataLoader` reached the
database through exactly three primitives: `.rpc()`, `.table().select()`, and
`.range()` pagination. Those are now a `DBBackend` protocol with two
implementations — `SupabaseBackend` (PostgREST, unchanged behaviour) and
`LocalBackend` (SQLAlchemy + psycopg3). **The ~800 lines of result-shaping in the
loader are untouched**: same RPC names, same params, same return shapes. Both
backends call the *same* SQL functions from `apps/api/migrations/`, so
`migrations/` stays the single source of truth.

Two PostgREST fidelity details the local path had to reproduce:

- **`RETURNS jsonb` vs `RETURNS TABLE`.** Four functions (`get_mood_contexts`,
  `get_reflective_insights`, `get_weekend_weekday_comparison`, `get_flashback`)
  return a scalar jsonb consumed as the object itself; the rest return row lists.
  Verified empirically against Postgres 16: a scalar-returning function yields one
  column named after the function, so `LocalBackend.rpc` unwraps exactly that case.
- **JSON type coercion.** PostgREST serialises over JSON, so callers receive
  timestamps as ISO-8601 strings and numerics as floats; psycopg returns native
  `datetime` / `Decimal` / `UUID`. `_jsonify` normalises them. Without it,
  `get_monthly_data` failed with `'datetime.datetime' object is not subscriptable`
  and six delegated methods raised `TypeError` — all of which the loader's
  except-and-return-empty would have hidden as blank charts.

**2. Lazy instantiation.** `supabase_data` is now a `_LazyLoader` proxy that
constructs on first attribute access, so `import app.main` succeeds with no
credentials. All ~35 route call sites are unchanged.

**3. Config (`app/config.py`).** First centralised env handling in the repo.
Real environment variables win over `spotify-insights.env` (how Compose injects).
`DB_BACKEND` defaults to `supabase`; `CORS_ORIGINS` defaults to the same four
origins as before.

**4. Migration runner (`db/migrate.py`).** Applies `migrations/*.sql` in filename
order, one transaction per file, recorded in `schema_migrations`. Supports
`--dry-run`, `--status`, `--database-url`. Tracking is required rather than
optional because `001` uses bare `CREATE INDEX` / `CREATE MATERIALIZED VIEW` and
is not replay-safe. Files carrying their own `BEGIN;`/`COMMIT;` (003/005/007) have
those stripped so they nest correctly.

**5. Seeder (`scripts/seed_local_db.py`).** Loads the committed synthetic fixture
by default, or `--from-dir` for a real export. Refuses to run against a non-empty
table (Compose runs it on every `up`), keeps exactly one `is_primary` user, splits
the fixture across two users so the comparison page has data, excludes `ip_addr`,
and finishes with a **non-concurrent** `REFRESH MATERIALIZED VIEW` — `refresh_all_views()`
uses `CONCURRENTLY`, which errors on a never-populated view.

**6. Parity script (`scripts/check_backend_parity.py`).** Diffs all 34 loader
methods across both backends. Phase 16's CI can reuse it.

**7. Self-contained API image.** The API builds from the **repo root** context
(`dockerfile: apps/api/Dockerfile`) so the committed synthetic fixture is baked
into the image at `/app/data/fixtures`. The stack therefore seeds itself without
depending on a bind mount resolving — caught by testing a genuine fresh clone,
where `./data` mounted empty and seeding crashed. A root `.dockerignore`
excludes `.git`, `.venv`, `node_modules`, `outputs/` and all of `data/` except
the fixture, keeping ~800 MB out of the build context. Compose still mounts the
host `./data` over it for real exports.

### Implementation

Migration **002 is recorded as applied without being executed**. Every function
in it is redefined by 004 with an added `p_user_id UUID DEFAULT NULL`; because
both variants have all-default arguments, applying both makes calls ambiguous.
Reproduced on Postgres 16 before choosing the fix:

```text
ERROR:  function get_top_artists(limit_count => integer) is not unique
```

The local path uses PostgreSQL named-argument syntax (`limit_count => :limit_count`),
so an omitted key falls through to the function's `DEFAULT`. That is what preserves
the loader's `_uid()` contract: leaving out `p_user_id` lets SQL's
`_effective_user_id()` resolve to the primary user, keeping the three-way
Python/SQL/frontend convention intact.

### Flow

`docker compose up` → `db` healthy (`pg_isready`) → `api` runs `migrate.py`, then
`seed_local_db.py`, then uvicorn → `web` proxies `/api` and `/health` to
`http://api:3011` over the compose network.

### Usage

```bash
docker compose up --build          # web :3010, api :3011, db :5433
./start.sh                         # unchanged Supabase path
cd apps/api && python db/migrate.py --dry-run
python scripts/check_backend_parity.py --tolerant
```

## Conclusion

The app now runs from a clean clone with one command and no accounts, which
unblocks Phases 11–12 and makes the repo reviewable. The backend switch was kept
behind a three-method interface rather than a second loader, so the two paths
cannot silently diverge — a decision that pays off directly in Phase 14's loader
collapse. The parity script proved its worth immediately, surfacing two real
type-fidelity bugs that the loader's swallow-and-return-empty error handling
would otherwise have shipped as blank charts.
